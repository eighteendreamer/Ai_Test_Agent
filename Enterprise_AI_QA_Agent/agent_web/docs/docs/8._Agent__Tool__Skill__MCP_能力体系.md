## 8. Agent / Tool / Skill / MCP 能力体系

### 8.1 Agent 注册中心

`AgentRegistry`（`registry/agents.py`）注册全部智能体，每个 Agent 声明 key、role、summary、supported_tools、supported_skills、supported_models、default_model、tags。核心 Agent：

| Agent key | 名称 | 角色 | 用途 |
|-----------|------|------|------|
| `coordinator` | Coordinator | coordinator | 规划、上下文装配、执行路由编排 |
| `qa-planner` | QA Planner | planner | 需求拆解为测试覆盖、断言、风险 |
| `ops-executor` | Ops Executor | worker | 终端命令、环境诊断、工作区运维检查 |
| `ui-executor` | UI Explorer | worker | ARIA 快照页面探索与语义 UI 图谱构建 |
| `api-verifier` | API Verifier | verifier | API、负载、结构化断言校验 |
| `report-analyst` | Report Analyst | — | 证据汇总成交付级报告 |

> 各测试模式还会注册自己的专属 Agent 与 Worker（见第 5 章）。

### 8.2 Tool 注册中心

`ToolRegistry`（`registry/tools.py`）注册全部工具，声明分类、权限级别（safe / ask）、输入输出 Schema、是否流式、默认启用、关联 Agent。前端「后端注册服务」按安全/需审批分组展示。

### 8.3 Skill 体系

`SkillRegistry`（`registry/skills.py`）= **15 个内联基础技能描述符** + 启动时扫盘 `src/SKILLS/*/SKILL.md`（54 个目录）合并，最终注册 **54 个技能**。

`reload()` 先复制 `_base_skills`，再用 `_load_filesystem_skills()` 遍历 `SKILLS/*/SKILL.md`：已存在的 key 保留内联的 `summary` / `recommended_agents` / `tool_keys`，只更新 `name` / `description` 并追加 `skill-file` 标签；未登记的 key 则按 frontmatter 建描述符，`recommended_agents` 默认 `["coordinator"]`、`tool_keys` 取自 frontmatter 的 `tools`。

内联登记（带 Agent 与工具绑定）的 15 个 key：

| Skill key | 用途 |
|-----------|------|
| playwright-cli | CLI 形态浏览器自动化命令（映射 Python Playwright 运行时） |
| playwright-e2e-testing | Playwright E2E 测试 |
| ci-pipeline-review | CI 流水线的并行化、缓存、选择性执行与失败可见性审查 |
| test-coverage-review | 把变更路径映射到测试，找出未覆盖分支与失败路径 |
| flaky-test-analysis | 不稳定用例归因与治理 |
| tdd-review | 以 TDD 视角评审实现 |
| test-data-strategy | 测试数据合成与治理 |
| owasp-security-testing | OWASP 面向的漏洞测试 |
| auth-security-testing | 认证/授权安全测试 |
| input-validation-security-testing | 输入校验类漏洞测试 |
| api-contract-testing | 接口契约测试 |
| api-test-generation | 从文档生成接口测试 |
| k6-load-testing | k6 负载测试 |
| jmeter-load-testing | JMeter 负载测试 |
| smoke-test-planning | 冒烟方案设计与准入判定 |

> 其余 39 个技能包（如 `pytest-testing`、`cypress-e2e-testing`、`appium-mobile-testing`、`visual-regression-testing`、`agently-mail` …）只以 `SKILL.md` 存在，无内联绑定。安全模式实际引用的 skill keys 是 `owasp-security-testing` / `auth-security-testing` / `input-validation-security-testing` 三个（见 `modes/security_testing_mode/skills.py`）；早期文档里写的 `vulnerability-analysis`、`network-reconnaissance` 在源码中并不存在，只在遗留 `.pyc` 缓存里还能搜到。

### 8.4 MCP（Model Context Protocol）

`MCPRegistry` 内置：

| MCP | 传输 | 状态 | 能力 |
|-----|------|------|------|
| Browser MCP | stdio | ready | inspect-page、browser-automation、browser-control |
| Filesystem MCP | stdio | ready | read-file、write-file、write-artifact、list-dir |
| Knowledge MCP | http | planned | search、fetch-document |
| Issue Tracker MCP | http | planned | create-issue、update-issue、query-issue |

外部 MCP 可通过「工具中心 → 插件导入」接入与统一管理，支持 stdio / 远程 endpoint 及 JSON 配置导入。
