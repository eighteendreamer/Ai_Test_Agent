# 测试用例设计

先读取需求、验收标准、接口/页面事实、风险和项目约定；不把缺失信息补成猜测。测试设计矩阵和模板按需读取 `references/source-1.md`。

## 输入契约

必须标明需求版本、验收标准、受影响模块、用户角色、数据约束、已知缺陷、执行环境和不可执行前置；缺失项进入待确认清单。

## 工作流程

1. 建立需求—风险—场景—断言的追溯关系，标记来源和不确定项。
2. 对每个规则使用等价类、边界值、状态转换、组合和错误路径，控制组合爆炸。
3. 每条用例写明前置、输入、动作、可观察结果、清理、优先级和证据。
4. 优先覆盖高风险、核心链路、权限、数据完整性、兼容性和回归样本。
5. 让用户确认会产生写入或外部影响的执行计划；生成用例不等于执行。
6. 导出前检查重复、孤立需求、无断言步骤和不可执行前置。

## 设计门禁

1. 每条用例绑定需求/风险来源和可观察断言，区分事实、假设与待确认项。
2. 组合输入使用等价类、边界值、状态转换和风险优先级控制组合爆炸。
3. 高风险用例优先覆盖权限、数据完整性、并发、错误恢复和真实回归样本。
4. 任何会写入外部系统的执行步骤必须单独标注授权、清理和回滚，不因“生成用例”而默认执行。

## 输出

输出追溯矩阵、用例（前置/输入/动作/断言/清理/优先级/证据）、覆盖缺口、假设和待确认问题；没有 Runner 结果不得给通过结论。

## 输出边界

区分需求事实、设计假设、待确认问题和已验证证据；没有 Runner 结果时不得给出通过结论。
