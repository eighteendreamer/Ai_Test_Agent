# 测试用例设计

先读取需求、验收标准、接口/页面事实、风险和项目约定；不把缺失信息补成猜测。

## 工作流程

1. 建立需求—风险—场景—断言的追溯关系，标记来源和不确定项。
2. 对每个规则使用等价类、边界值、状态转换、组合和错误路径，控制组合爆炸。
3. 每条用例写明前置、输入、动作、可观察结果、清理、优先级和证据。
4. 优先覆盖高风险、核心链路、权限、数据完整性、兼容性和回归样本。
5. 让用户确认会产生写入或外部影响的执行计划；生成用例不等于执行。
6. 导出前检查重复、孤立需求、无断言步骤和不可执行前置。

## 输出边界

区分需求事实、设计假设、待确认问题和已验证证据；没有 Runner 结果时不得给出通过结论。
