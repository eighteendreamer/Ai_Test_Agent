# k6 负载测试

通过性能模式现有 `perf-plan-compiler`、`perf-engine-select`、`performance-test-runner` 和结果分析器使用 k6。不要直接绕过目标安全护栏，也不要假设宿主机已安装 k6；由现有运行时选择本地或容器后端。

## 工作流程

1. 明确目标、环境、允许负载、持续时间、到达率/VU、SLA 和停止条件；生产环境默认禁止。
2. 根据业务选择 baseline、load、stress、spike 或 soak，并给出可解释的 ramp stages。
3. 为请求声明方法、URL、headers、body、数据参数、关联提取和业务断言。
4. 将 p95/p99、错误率、吞吐和业务失败率写成阈值，避免只看平均响应时间。
5. 先运行低负载 smoke，验证 URL、认证、数据和脚本，再执行正式负载。
6. 保留原始 summary、退出码、阈值结果和容器日志，由独立 analyst 给出 verdict。

## 设计门禁

场景必须说明 arrival-rate 或 VU 模型、数据相关性、认证刷新、检查（checks）和阈值（thresholds）的业务含义。先用单个虚拟用户验证脚本，再逐级增加负载；任何达到停止条件的运行都要立即终止并记录原因。将引擎错误、脚本错误、目标 4xx/5xx、网络失败和资源饱和分开归因。

## 输出

输出负载模型、SLA/阈值、环境与授权、实际运行命令、原始指标、退出码、资源证据、基线对比和 verdict；没有执行结果时只输出计划。

## 安全与准确性

- 未确认目标、授权和 SLA 时不发压。
- 不把网络、目标应用、脚本或环境错误混成性能退化。
- 不用无限 VU、无界持续时间或自动重试放大风险。
- 报告必须区分引擎阈值、系统独立判定和基线比较。
