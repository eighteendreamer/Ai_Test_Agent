# TDD 代码审查

检查实现是否由可复现的行为测试驱动。代码审批不强制团队采用 TDD，但当任务声明测试优先或修复行为缺陷时，必须审查红-绿-重构证据。

## 审查要点

1. 是否存在来自真实失败输入的回归测试，并且在修复前因正确原因失败。
2. 测试是否描述可观察行为、边界和错误契约，而不是实现细节或无意义的 mock 调用。
3. 生产代码是否只实现使测试通过所需的最小行为，随后重构是否保持测试绿色。
4. 是否覆盖空输入、异常、状态转换、权限和外部依赖失败等风险分支。
5. 是否有 `skip`、`only`、过宽 mock、永真断言或把失败捕获后忽略的反模式。

## 结论格式

记录测试文件、失败/通过证据来源、行为范围和仍未覆盖的风险。没有运行日志时不要虚构红绿阶段，只能标记为“需要验证”。
