# TDD 代码审查

检查实现是否由可复现的行为测试驱动。代码审批不强制团队采用 TDD，但当任务声明测试优先或修复行为缺陷时，必须审查红-绿-重构证据。

## 审查要点

1. 是否存在来自真实失败输入的回归测试，并且在修复前因正确原因失败。
2. 测试是否描述可观察行为、边界和错误契约，而不是实现细节或无意义的 mock 调用。
3. 生产代码是否只实现使测试通过所需的最小行为，随后重构是否保持测试绿色。
4. 是否覆盖空输入、异常、状态转换、权限和外部依赖失败等风险分支。
5. 是否有 `skip`、`only`、过宽 mock、永真断言或把失败捕获后忽略的反模式。

## 结论格式

记录测试文件、失败/通过证据来源、行为范围和仍未覆盖的风险。没有运行日志时不要虚构红绿阶段，只能标记为“需要验证”。

## 红-绿-重构证据

红阶段必须来自真实、最小、可重复失败输入，记录命令、退出码、异常/断言和正确失败原因；缺依赖、路径错误等环境失败不能算红阶段。绿阶段运行新增回归和原有相关测试，确认实现未吞错、放宽校验或改变无关契约。重构阶段只改善结构，不同时改变未被测试描述的语义，并比较前后公开行为、日志、性能和清理。

## 审查门禁

重点检查空值、异常、状态、权限、外部依赖失败、`skip/only`、过宽 mock、永真断言、捕获后忽略失败和只验证实现细节。需要 TypeScript/Jest、Python/pytest、三角测量、AAA、边界排序和反模式示例时加载 `references/source-1.md`。
