# 输入校验安全测试

沿“外部输入 → 规范化/校验 → 业务规则 → 危险汇点”追踪数据。不要把客户端校验视为安全边界；动态 payload 只能通过安全模式 Runner 在已授权目标执行。

## 检查范围

- 类型、长度、范围、枚举、必填、重复字段和 Unicode/编码规范化。
- SQL/NoSQL/命令/模板/路径/XSS 注入与输出编码。
- 文件名、MIME、扩展名、大小、内容检测、存储路径和下载响应。
- CSRF、重复提交、速率限制、验证码和错误信息泄露。
- 客户端与服务端规则不一致、解析器差异和批量赋值。

## 输出与执行

为每条场景记录入口、危险汇点、预期拒绝、证据和清理动作。先做静态审查和低风险边界验证；高影响 payload、写操作和上传必须显式审批。不得记录敏感原始数据或把扫描器告警直接当成已确认漏洞。

## 输入追踪与向量

记录来源（URL/body/header/file/cookie/message）、解析器、规范化、验证规则、业务转换、危险汇点、输出编码、失败响应和清理。覆盖空/缺失/重复/未知字段、错误类型、Unicode/规范化、长度/数值/日期边界、SQL/NoSQL/命令/模板/路径/XSS/CRLF、上传 MIME/扩展名/大小/内容签名/存储路径，以及 CSRF、重复提交、验证码、速率和错误信息。

## 动态执行门禁

先做静态追踪和低风险边界验证；高影响 payload、上传、写操作和速率实验必须有授权、目标、最大次数、清理和停止条件。保存脱敏请求、响应、状态、证据和最小复现。需要完整向量、Playwright、API、上传、CSRF、速率和错误消息细节时读取 `references/source-1.md`。
