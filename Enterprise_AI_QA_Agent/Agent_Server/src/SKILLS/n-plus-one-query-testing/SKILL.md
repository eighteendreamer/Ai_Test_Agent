# N+1 查询测试

以项目现有数据库、ORM、日志/APM 和测试设施为依据；不要凭候选资料假设特定 APM 或查询接口。

## 工作流程

1. 确定列表、树、批量加载或序列化等高风险入口及其业务数据规模。
2. 在小、中、大数据集上记录请求、查询数量、重复语句模式和耗时。
3. 判断查询数是否随记录数线性增长，并关联到代码调用链和加载策略。
4. 区分 N+1、缺索引、大结果集、锁等待和缓存冷启动，避免只凭总耗时下结论。
5. 修复后同时验证结果正确性、查询数上界、内存和分页行为。
6. 保留数据规模、查询证据、环境、基线和前后对比。

## 审查重点

- 测试数据太小导致无法暴露增长趋势。
- 用全局缓存掩盖单请求 N+1。
- eager loading 修复引入笛卡尔积或内存放大。

## 输出边界

没有查询/APM 证据时标记为风险假设，不声称已发现确定的 N+1。
