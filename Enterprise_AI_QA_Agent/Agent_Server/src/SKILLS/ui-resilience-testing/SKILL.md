# UI 韧性测试

异常交互必须在获准环境中执行，先定义可逆性、速率、账号、数据清理和停止条件；不得对生产环境做随机破坏性操作。动作矩阵和证据字段按需读取 `references/source-1.md`。

## 输入契约

确认目标页面/用户任务、可写数据范围、浏览器能力、后端可观察指标、授权环境、最大并发/频率和紧急停止方式。

## 工作流程

1. 从重复提交、快速切换、返回/刷新、断网/重连、过期会话和长输入建立风险矩阵。
2. 为每个动作限定最大频率、持续时间、写入范围和停止条件。
3. 断言无重复业务记录、无未授权状态、无丢失确认、无永久加载和可恢复错误提示。
4. 采集动作序列、时间戳、请求、UI 状态、控制台、截图和后端可观察结果。
5. 发现失败后使用最短确定性序列重放，不用继续随机点击扩大影响。
6. 清理测试数据并验证系统恢复到已知状态。

## 韧性断言

- 重复点击/并发提交：最多一个业务记录、幂等响应和按钮状态一致。
- 刷新/返回/导航：草稿、提交结果、权限和 URL 状态不丢失或错误恢复。
- 断网/重连/过期会话：明确重试上限、错误提示、恢复路径和不会重复写入。
- 异常输入/长任务：无永久 loading、无未捕获异常、资源和焦点最终释放。

## 安全门禁与输出

每个动作必须有速率、时长、写入范围、停止条件和清理步骤；发现失败立即缩减为最小确定性序列。输出动作种子、时间线、请求/UI/控制台证据、影响、复现和恢复验证。无受控 Runner 时只输出模型。

## 执行边界

没有受控浏览器/环境和明确授权时只输出测试模型；当前新增模式没有专用 Runner。

## 输出

输出种子/动作序列、频率、断言、证据、影响和最小复现。
