# Cypress E2E 测试

先读取 Cypress 版本、config、support、fixtures、CI 命令和应用启动方式；不要假设 Cypress Runner 已接入当前系统。命令与网络拦截差异按需读取 `references/source-1.md`。

## 输入契约

确认用户旅程、环境、登录/数据前置、应用启动方式、浏览器矩阵、写入范围和失败证据目录。

## 工作流程

1. 从用户旅程定义前置、操作、断言、清理和证据。
2. 使用稳定 data 属性或语义选择器，避免脆弱 CSS 和坐标。
3. 网络拦截必须对应真实契约，并覆盖成功、错误、延迟和重试。
4. 依赖 Cypress 重试机制和可观察条件，不使用固定 sleep。
5. 覆盖认证、刷新、跨页面、错误恢复和写操作隔离。
6. 运行项目已有 Cypress 命令并保留视频、截图、日志和退出码。

## 质量门禁

1. 选择器优先使用稳定 `data-*` 或语义角色；禁止坐标、动态 class 和脆弱层级。
2. intercept 必须对应真实 API 契约，覆盖成功、错误、延迟、重试和未处理请求。
3. 使用 Cypress 可观察重试条件，避免固定 sleep；跨页面、刷新、认证和写操作声明清理。
4. 断言用户可观察结果、URL、数据和错误恢复，不只断言请求被调用。
5. 失败按选择器、同步、网络、环境和产品原因分类，保留视频/截图/日志。

## 输出

输出场景矩阵、选择器/拦截风险、数据隔离、实际命令和退出码；当前无 Cypress Runner 时只做审查或迁移建议。

## 执行边界

当前 UI Runner 基于 Playwright；没有 Cypress Runner 时只做代码审查/迁移建议，不声称执行 Cypress。
