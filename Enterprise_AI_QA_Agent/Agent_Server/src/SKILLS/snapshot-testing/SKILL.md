# 快照测试

快照只适合稳定、可读且值得逐行审查的输出；它不能替代业务行为断言。执行前先读取 `references/source-1.md`，并以仓库现有 runner、序列化器和基线目录为准。

## 输入契约

- 目标：组件树、序列化对象、GraphQL/API 响应或已批准的视觉基线。
- 必须取得：变更说明、当前快照 diff、生成命令、运行环境和预期稳定字段。
- 缺少实际 diff 时只能提出审查清单，不能批准基线更新。

## 工作流程

1. 确认快照对象的业务价值、稳定字段和预期变更来源。
2. 移除或固定时间、随机 ID、路径、顺序和环境噪声，不通过宽泛序列化掩盖问题。
3. 保持快照足够小，使审批者能够理解每一处差异。
4. 对关键状态码、权限、计算结果和副作用补充显式断言。
5. 基线更新必须关联需求或已审查变更，不能以“让测试通过”为理由批量接受。
6. 运行项目现有快照命令并审查实际 diff、退出码和更新数量。

## 决策门禁

1. 若输出包含时间、随机 ID、绝对路径、机器名或未排序集合，先修复测试确定性，再评估快照。
2. 若一次变更更新超过约定范围，按文件和字段聚类差异；找不到共同根因则拒绝批量接受。
3. 对状态码、权限、金额、列表长度、错误码和副作用使用显式断言；快照只保留结构细节。
4. 允许使用 serializer/matcher 隐藏无业务价值的噪声，但必须在测试旁说明隐藏原因。
5. 基线更新需关联 issue/PR、人工审查者和生成环境，CI 不得自动提交未审查快照。

## 失败分类与证据

- **真实回归**：业务字段或可见状态意外变化；保留 before/after、最小复现和调用链。
- **预期变更**：有需求或设计证据；更新基线并记录影响范围。
- **不稳定**：同一提交重复运行结果不同；收集 seed、时间、网络和排序证据后先稳定化。
- **测试设计缺陷**：快照过大、不可读或只验证实现细节；拆分快照并补行为断言。

## 输出模板

输出目标与环境、命令和退出码、差异摘要、每个基线的保留/拆分/更新/拒绝决定、显式断言缺口、风险等级和回归命令。按需读取 `references/source-1.md` 的框架配置和示例，不把参考全文注入默认上下文。

## 风险信号

- 一个快照包含整个页面、随机数据或无关实现细节。
- 大量基线同时变化但没有共同根因说明。
- CI 自动更新并提交快照，绕过人工审查。
- 用属性匹配器忽略真正需要验证的业务字段。

## 输出边界

报告每个基线的保留、拆分、显式断言或拒绝更新建议；未看见 diff 时不得批准更新。
