# JMeter 负载测试

通过性能模式现有引擎选择、计划编译、容器管理和结果解析能力使用 JMeter。运行时负责生成 JMX、选择本地/容器后端并以非 GUI 模式执行；不要编造未注册插件或协议支持。

## 工作流程

1. 明确目标、线程数、ramp、循环/持续时间、SLA、认证和数据依赖。
2. 将多步骤流程拆成 sampler、关联变量、前置处理、断言和清理动作，避免线程间共享可变状态。
3. 先执行 smoke，确认 JMX、目标连通性、响应解析和统计输出有效。
4. 正式执行使用非 GUI 模式，保留 statistics/summary、JTL、退出码和容器日志。
5. 分析吞吐、错误率、平均值、p95/p99、连接错误和业务断言失败，并与 SLA/基线独立交叉验证。

## 反模式

- 在 GUI 模式下正式压测。
- 无边界线程、循环或持续时间。
- 只看平均响应时间或把所有非 2xx 当成同一种失败。
- 使用生产凭据、真实隐私数据或不可清理写操作。
- 把 JMeter 插件能力当作系统已经安装。
