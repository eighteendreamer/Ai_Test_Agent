# JMeter 负载测试

通过性能模式现有引擎选择、计划编译、容器管理和结果解析能力使用 JMeter。运行时负责生成 JMX、选择本地/容器后端并以非 GUI 模式执行；不要编造未注册插件或协议支持。

## 工作流程

1. 明确目标、线程数、ramp、循环/持续时间、SLA、认证和数据依赖。
2. 将多步骤流程拆成 sampler、关联变量、前置处理、断言和清理动作，避免线程间共享可变状态。
3. 先执行 smoke，确认 JMX、目标连通性、响应解析和统计输出有效。
4. 正式执行使用非 GUI 模式，保留 statistics/summary、JTL、退出码和容器日志。
5. 分析吞吐、错误率、平均值、p95/p99、连接错误和业务断言失败，并与 SLA/基线独立交叉验证。

## 反模式

- 在 GUI 模式下正式压测。
- 无边界线程、循环或持续时间。
- 只看平均响应时间或把所有非 2xx 当成同一种失败。
- 使用生产凭据、真实隐私数据或不可清理写操作。
- 把 JMeter 插件能力当作系统已经安装。

## 计划组件与线程模型

将线程组、HTTP sampler、控制器、定时器、断言、提取器、数据集和监听器映射到业务流程。每个变量声明来源、作用域、失败行为和脱敏策略；线程间不得共享可变 token、文件或业务记录。先用单线程/少量循环验证，再选择固定 VU、ramp、吞吐、峰值或浸泡模型，并明确 SLA、停止条件和目标环境。

## 断言、证据与运行

分别记录状态码、响应断言、JSON Path、响应时间、业务字段和错误结构；提取器失败、缺字段、空 token、重定向和非 2xx 不得静默继续。通过现有性能模式生成/编译 JMX，先执行 smoke，再由 `performance-test-runner` 运行；保存 JTL、statistics、summary、容器日志、退出码和阈值。需要组件、线程、控制器、定时器、提取器、CSV 和 CLI 细节时读取 `references/source-1.md`。
