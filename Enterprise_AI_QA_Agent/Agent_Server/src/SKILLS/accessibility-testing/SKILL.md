# 无障碍测试

自动扫描只能发现部分问题。先确认目标标准、页面状态、浏览器和辅助技术范围，再组合自动与人工证据。规则映射和人工检查矩阵按需读取 `references/source-1.md`。

## 输入契约

收集关键用户任务、页面/组件状态、目标 WCAG 版本与 conformance、浏览器/缩放、键盘和屏幕阅读器范围、现有 axe 配置及执行命令。

## 工作流程

1. 建立页面、组件、交互状态和关键用户任务清单。
2. 若项目已有 axe/Playwright 无障碍集成，按实际配置运行并保留 rule、节点和影响级别；不要假设依赖存在。
3. 仅使用键盘完成关键任务，检查焦点顺序、可见焦点、陷阱、跳转和弹层焦点恢复。
4. 核对 landmark、heading、name/role/value、表单标签、错误关联和动态状态通知。
5. 检查缩放、重排、颜色对比、非颜色提示、媒体替代和减少动画偏好。
6. 将每个问题关联到页面状态、操作、实际结果、标准条款和证据。

## 检查门禁

1. 自动扫描结果必须包含 rule、节点、影响级别、页面状态和工具版本；不能直接等同合规结论。
2. 键盘执行覆盖跳过链接、焦点顺序/可见性、弹层陷阱与恢复、表单错误和动态通知。
3. 结构检查覆盖 landmark、heading 层级、name/role/value、标签、关联描述和状态属性。
4. 检查缩放/重排、对比度、非颜色信息、动画偏好、媒体替代和触摸目标。
5. 每个问题标记自动发现、人工复现、需辅助技术复核或未验证，并给出回归步骤。

## 输出

输出任务/状态矩阵、工具与标准依据、问题证据、用户影响、优先级、修复建议和回归命令；没有专用 Runner 时不得声称认证通过。

## 执行边界

当前系统没有专用 axe 或屏幕阅读器 Runner 时，只做静态审查、浏览器可达性探索和测试方案；不得声称完成 WCAG 合规认证。

## 输出

区分自动发现、人工复现、需辅助技术复核和无法验证；给出用户影响及修复后的回归步骤。
