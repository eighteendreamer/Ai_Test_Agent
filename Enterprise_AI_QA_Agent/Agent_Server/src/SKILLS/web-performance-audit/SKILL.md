# Web 性能审计

先确认审计工具、浏览器、网络/CPU 模拟、页面状态和基线；不要将单次实验室分数当作真实用户结论。指标解释和采样矩阵按需读取 `references/source-1.md`。

## 输入契约

确认 URL/登录态、页面版本、设备、网络/CPU、缓存冷热、采样次数、工具版本和目标指标。

## 工作流程

1. 定义 URL、登录状态、设备、网络、缓存冷热、采样次数和版本。
2. 记录 LCP、INP、CLS、TTFB、资源瀑布、JS/CSS 体积和错误。
3. 区分实验室指标、现场数据、业务交互和后端瓶颈。
4. 对每项建议关联资源/代码证据、用户影响、风险和回归指标。
5. 重复采样并报告波动范围，禁止只挑最好分数。
6. 保存原始报告、配置、页面版本和退出码。

## 审计门禁

1. 区分实验室指标、现场数据、业务交互和后端瓶颈，报告中标注测量来源。
2. 至少重复采样并报告中位数/范围及异常；不得只选择最好分数。
3. LCP、INP、CLS、TTFB、资源瀑布、JS/CSS 体积和错误均需关联页面/代码证据。
4. 建议必须包含用户影响、优先级、风险、修复后指标和回归命令。

## 输出

输出采样配置、原始/汇总指标、波动、瓶颈证据、建议与回归门禁；当前没有 Lighthouse Runner 时不得声称完成自动审计。

## 执行边界

当前没有 Lighthouse 专用 Runner；可复用浏览器探索但不得声称完成 Lighthouse/PageSpeed 自动审计。
