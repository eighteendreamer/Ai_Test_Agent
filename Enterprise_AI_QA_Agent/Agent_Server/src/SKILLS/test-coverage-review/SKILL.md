# 测试覆盖审查

关注变更风险与测试证据的对应关系，不把单一覆盖率百分比当成质量结论。没有真实覆盖率报告时，明确标注为静态推断。

## 审查流程

1. 从 diff 提取新增/修改的函数、分支、状态转换、异常处理、权限判断和外部调用。
2. 搜索对应测试，建立“变更路径 → 用例/断言 → 执行证据”映射；没有映射的路径列为缺口。
3. 优先检查错误、超时、空值、边界、并发、重试、回滚和权限失败路径，而不是只看 happy path。
4. 检查覆盖率工具和阈值是否覆盖正确的源码范围，排除项是否有理由且没有排除业务代码。
5. 检查变更覆盖门禁是否只要求行覆盖，是否遗漏分支、函数、条件或关键模块门禁。
6. 区分未测试代码、不可达代码和生成/供应商代码，不能把三者混为一谈。

## 反模式

- 只提高阈值或补一条浅断言来掩盖缺口。
- 大面积增加 `coverage ignore`、`skip`、`only` 或空测试。
- 只验证返回值，不验证副作用、状态和错误契约。
- 测试存在但没有被 CI 收集或报告。

## 输出

输出缺口清单、风险等级、受影响路径、现有证据和建议用例。建议应能直接转成回归测试，不要求审批阶段自动生成或运行测试。
