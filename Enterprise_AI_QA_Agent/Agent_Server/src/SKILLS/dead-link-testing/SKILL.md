# 死链测试

先定义允许的域名、路径、认证状态、robots/速率、方法和环境；不得无边界爬取外部站点。状态分类与爬取策略按需读取 `references/source-1.md`。

## 输入契约

确认入口/sitemap、域名白名单、认证状态、最大 URL 数、并发/速率、超时、robots 约束和报告格式。

## 工作流程

1. 从 sitemap、页面 DOM、静态资源和用户指定入口收集候选链接并去重。
2. 区分页面、API、脚本、样式、图片、下载和锚点，使用适合的验证方法。
3. 记录状态码、最终 URL、重定向链、响应类型、超时和 TLS/网络错误。
4. 对需要认证、动态生成或有速率限制的资源标记不可直接判定。
5. 重复失败请求并保留入口、请求时间、环境和证据。
6. 修复后只复查受影响链接和关键入口。

## 判定门禁

1. 先规范化 URL、去重并限制域名/路径，保留入口来源。
2. 页面、API、静态资源、下载和锚点使用不同状态判定；重定向链必须完整记录。
3. 401/403、robots、动态资源、TLS 和超时标为不可直接判定，不等同死链。
4. 失败至少重试一次并记录时间、环境、最终 URL、响应类型和错误；禁止高频重试。

## 输出

输出扫描范围、候选总数、死链/阻断/未知分类、重定向链、入口、证据和复查命令；无专用 Runner 时不声称全站完成。

## 执行边界

当前没有独立死链 Runner；可在已有浏览器能力范围内规划，不能声称完成全站扫描。
