# 属性测试

先确认项目语言、已有属性测试库、runner 和 CI 资源；不要默认安装候选资料中的 fast-check 或其他框架。需要框架语法时按需读取 `references/source-1.md`。

## 输入契约

- 被测函数/状态机及其可观察输出。
- 业务不变量、输入约束、允许的失败类型、性能预算和可复现环境。
- 现有示例测试、已知线上缺陷和序列化格式，作为生成器覆盖依据。

## 工作流程

1. 用业务语言定义不变量，例如往返一致性、幂等、单调性、守恒或等价关系。
2. 描述有效与无效输入域、边界分布和前置条件，避免生成器只覆盖常见值。
3. 保留失败 seed、最小反例、运行参数和版本，使失败可重放。
4. 检查过度过滤和无效前置条件，确认测试实际探索了足够输入。
5. 将发现的真实反例固化成清晰的回归用例，再修复根因。
6. 运行仓库已有测试命令并记录次数、seed、缩减过程和退出码。

## 生成器设计门禁

1. 先列输入域分区：空值、边界、Unicode、极值、重复、顺序、非法组合和状态序列，再实现生成器。
2. 生成器必须保持有效样本比例可解释；禁止用过度过滤隐藏未覆盖区域。
3. 为每个属性写清前置条件、关系方向和反例判定，避免把实现代码复制为 oracle。
4. 设定运行次数、超时、seed 记录和并行策略；CI 失败必须可用同一 seed 重放。
5. 缩减后的最小反例应转成稳定回归用例，并链接原始 seed 与业务缺陷。

## 常用属性模型

- 往返：`decode(encode(x)) == normalize(x)`。
- 幂等：重复执行不改变最终状态。
- 守恒/单调：总量不凭空增减，排序或过滤满足序关系。
- 等价实现：批量与逐项、缓存命中与未命中产生同一业务结果。
- 状态机：每个动作只允许进入定义的状态和错误转移。

## 输出与失败分类

报告属性、生成域覆盖、次数/seed、最小反例、环境、退出码和是否已固化回归。区分生成器缺陷、oracle 缺陷、产品缺陷、资源超时；没有执行报告时不得宣称发现缺陷。

## 审查重点

- 属性是否只是重复实现被测函数。
- 生成器是否遗漏空值、极值、Unicode、顺序、重复和状态序列。
- 不确定性是否因未记录 seed 而不可复现。

## 输出边界

没有实际框架和执行证据时，只输出属性、生成域和预期反例格式。
