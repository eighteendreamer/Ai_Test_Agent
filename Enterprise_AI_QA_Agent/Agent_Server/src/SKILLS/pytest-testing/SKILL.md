# Pytest 测试

先读取项目依赖、pytest 配置、同类测试和真实运行命令；不要从候选资料假设插件已经安装。

## 工作流程

1. 将目标行为拆成正常、边界、异常和状态转换，优先使用真实失败样本。
2. 复用项目已有 fixture 层级和命名；明确 fixture 的 scope、清理动作与共享状态风险。
3. 用参数化表达同一行为的输入矩阵，避免复制测试正文或把不同语义硬塞进一个用例。
4. 对异常检查类型和稳定的业务信息；对异步行为使用项目已配置的异步测试方式。
5. 通过临时目录、事务回滚、固定随机种子或依赖替身隔离文件、数据库、时间和网络。
6. 实际运行项目声明的最小测试命令，再按风险扩大范围；保留 stdout、stderr 和退出码。

## 审查重点

- fixture 是否隐藏关键前置条件、跨测试泄漏状态或扩大了不必要的 scope。
- marker、skip、xfail 和重试是否有可核验理由，而不是掩盖缺陷。
- mock 是否替换正确边界，并仍验证可观察行为。
- 测试是否因正确原因失败，且断言没有只验证实现细节。

## 输出边界

区分已运行、静态审查和仅建议；没有测试输出时不得声称通过。
