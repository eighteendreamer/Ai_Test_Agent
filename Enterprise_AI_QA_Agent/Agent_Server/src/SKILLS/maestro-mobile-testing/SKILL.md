# Maestro 移动端测试

先确认 Maestro CLI、平台支持、应用标识、设备 Provider 和仓库现有 flow 约定；不要凭候选文档生成未知命令。YAML flow 语法和子流程模式按需读取 `references/source-1.md`。

## 输入契约

确认设备/OS、应用标识、启动/清理状态、账号、参数、权限、网络和可执行 CLI。

## 工作流程

1. 将关键旅程拆成短小、单一目的且可独立重放的 flow。
2. 优先使用稳定 id 和可访问文本，避免坐标与位置依赖。
3. 明确 launch、清理状态、权限、账号、数据和环境参数。
4. 将重复但稳定的登录/导航抽成子流程，避免隐藏断言。
5. 对条件、重试和等待设置可观察完成标准，不掩盖产品卡死。
6. 收集命令输出、设备信息、截图、视频和失败步骤。

## Flow 门禁

1. 每个 flow 只覆盖一个可重放旅程，使用稳定 id/可访问文本，禁止坐标。
2. 等待必须绑定可观察完成条件；重试不能掩盖卡死或真实超时。
3. 子流程只抽取稳定准备步骤，断言仍需在主 flow 清晰可见。
4. 失败证据绑定 flow、设备、构建、步骤、截图/视频和退出码。

## 输出

输出 flow 清单、输入/断言、状态策略、命令和缺失设备条件；无 Runner 时只做 YAML 设计。

## 执行边界

当前无 Maestro CLI Runner/设备 Provider 时只输出 YAML 设计建议和执行前置，不声称流程可运行。

## 输出

输出 flow 清单、输入、断言、状态策略和缺失能力。
