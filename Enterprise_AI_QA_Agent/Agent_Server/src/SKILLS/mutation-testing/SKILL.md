# 变异测试

先核对项目已使用的变异工具、支持语言、runner 和配置；不要默认安装 Stryker 或复制候选命令。框架参数和报告字段按需读取 `references/source-1.md`。

## 工作流程

1. 先确保原始测试稳定通过，限定本次变更或高风险模块范围。
2. 运行项目声明的变异命令，保存配置、工具版本、耗时和完整结果。
3. 按存活、被杀死、无覆盖、超时和等价变异分类，不只看总分。
4. 对存活变异追溯到公开行为：补断言、补输入或证明为等价变异。
5. 对超时和崩溃分析测试隔离、资源限制与工具兼容性，不直接排除。
6. 门禁应基于风险和稳定基线，防止通过忽略文件制造分数。

## 运行前检查

- 原始测试必须在同一提交、同一环境先通过；保留基线退出码。
- 明确变异范围、排除规则、超时、并行度、资源上限和可接受运行时。
- 对生成的变异 diff 做安全审查，禁止把生产配置、密钥或真实数据带入运行。

## 分类处理

1. **存活**：检查是否缺少行为断言、错误分支、边界输入或副作用验证；补最小测试后重跑。
2. **无覆盖**：确认是否死代码、入口未注册或测试选择器遗漏，不能直接加入 ignore。
3. **超时/崩溃**：区分测试泄漏、资源限制、编译器/工具不兼容和等价变异，保留日志。
4. **等价变异**：给出语义证明、代码位置和工具配置依据，单独记录而非伪装为被杀死。

## 门禁与输出

门禁应关注新增高风险代码的趋势和分类，而不是追求全局单一分数。输出工具版本、范围、基线、分类计数、代表性 surviving diff、处理决定、退出码和重跑命令；没有实际报告不得给分数结论。

## 审查重点

- 新增 ignore、阈值下降或范围缩小是否有证据。
- 测试是否只覆盖代码执行而不能识别结果变化。
- 变异运行是否可重放并与代码版本关联。

## 输出边界

没有实际变异报告时，不给出分数或声称测试质量已验证。
