# API 测试场景生成

先建立接口清单和风险矩阵，再生成结构化场景；不要在没有文档或用户范围确认时盲目生成整套测试，也不要把生成结果当作已执行证据。

## 场景覆盖

- 每个方法的成功、缺少必填参数、类型/格式错误、边界值和未知字段。
- 未认证、权限不足、资源不存在、重复创建、冲突、限流和超时。
- 列表接口的分页、空结果、排序、过滤和游标边界。
- 创建/更新/删除的幂等性、资源清理、状态转换和并发冲突。
- 响应状态、headers、content-type、schema、错误码和敏感字段。

## 生成纪律

1. 每个场景引用 OpenAPI operationId、路径、schema 或业务约束。
2. 标注前置条件、数据依赖、执行模式（读/写/认证）和清理动作。
3. 为写操作设置资源锁和回滚/清理要求，避免测试顺序依赖。
4. 区分“建议场景”“已编译任务”“已执行结果”，不混淆状态。
5. 生成后交给用户或 API 模式计划阶段确认范围，再使用现有 runner 执行。

## 输出

输出可转成 API campaign 的场景矩阵：目标、请求、数据、断言、依赖、风险、证据要求和执行顺序。文档缺失时列出需要补充的信息。
