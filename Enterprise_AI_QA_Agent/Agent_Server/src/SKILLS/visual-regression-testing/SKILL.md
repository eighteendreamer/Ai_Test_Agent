# 视觉回归测试

先读取项目现有截图工具、基线位置、阈值、浏览器和 CI 环境；不要假设候选资料中的 Playwright Test runner 已安装。截图稳定化和差异分类按需读取 `references/source-1.md`。

## 输入契约

确认页面/组件状态、业务验收标准、视口/浏览器/主题矩阵、字体和数据种子、基线版本、像素阈值及存储位置。

## 工作流程

1. 选择有业务价值的页面/组件状态、主题、视口和浏览器矩阵。
2. 固定字体、动画、时间、随机数据、网络结果、滚动位置和加载完成条件。
3. 优先截取稳定语义区域；全页截图必须说明其审查价值和噪声控制。
4. 对动态但无关区域使用明确 mask；不得遮盖待验证内容。
5. 将实际、基线和差异图作为一组证据，记录像素阈值与环境信息。
6. 基线更新必须关联已批准视觉变更，由人工审查差异后执行。

## 稳定性与审查门禁

1. 固定字体、动画、时间、随机数、滚动位置、网络响应和加载完成条件；记录环境版本。
2. 选择语义区域优先；mask 只能覆盖已证明与需求无关的动态区，禁止遮盖待验证内容。
3. 每次比较保留实际图、基线图、差异图和阈值；按布局、字体、颜色、内容和渲染噪声分类。
4. 大范围差异先确认共享环境/字体/数据变化，再判断产品回归；不要用调高阈值消除失败。
5. 基线更新必须有 PR/需求证据和人工审查记录，CI 不得自动接受。

## 输出

输出状态矩阵、稳定化条件、环境、差异摘要、基线决策、未覆盖区域、执行命令和证据。无完整视觉 Runner 时仅提供方案和截图证据，不声称像素比对完成。

## 执行边界

当前系统可复用浏览器探索和截图能力，但没有完整视觉基线 Runner 时，只生成方案和证据，不声称完成自动像素比对。

## 输出

输出状态矩阵、稳定化条件、差异分类、基线决策和复现环境。
