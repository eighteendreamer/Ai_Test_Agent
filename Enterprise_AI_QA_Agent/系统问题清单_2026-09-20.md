## 五、横切根因（修复时应升级为架构问题看待）

1. **审批/安全标志位走参数通道**（P0-1/2/5/25/31/32、P1-34）：安全决策状态混在模型可控的 `arguments`/payload 字典里传递，无保留键剥离、无统一授权门——同一根因至少 7 处（含 mode_key 短路授权、plan 直传绕过评审、空列表 or 回落暴露隐藏工具）。建议：服务端侧信道（context 对象）传审批状态，入口处强制剥离 `_server_*` 保留键，mode 参数只允许 id 不允许内联对象。
2. **围栏机制不完整**（P0-3/4）：`<untrusted_content>` 有格式无防护（不转义闭合标签），且工具输出/摘要走另一套 `content_provenance` JSON 字段约定，两套并存。
3. **JSONB metadata 整读整写 vs SQL 增量写并存**（P0-19/20/21）：session 元数据无版本化乐观锁，多写者互相覆盖是结构性问题。
4. **async 端点里同步 I/O 无统一策略**（P1-1/2/3）：同文件内一半包 `to_thread` 一半裸调——缺"路由层禁止直接同步 I/O"的约定。
5. **stats 增量计算无守恒校验**（P1-7/8/9）：delta 与全量重算双轨并存且 delta 路径不完整。
6. **用例驱动红线多处被触碰**：条目重领（P0-16）、回归覆盖风险、attempt 无上限、smoke plan 直传（P0-32）、版本快照可覆盖（P1-31）——正是 `.qoder/rules` 第 7 章明令禁止的行为。
7. **进程单例持有可转会话态**（P1-33/56、P0-21 同族）：mode runtime / WorldState / 各类模块级 dict 在单例上累积 `_last_*` 实例属性，多会话必然串台。
8. **幂等/去重键设计未覆盖重试语义**（P0-33、P1-32、P1-6）：claim key 基于 task_ids 集合而非业务幂等意图，重试既可能换 key（uuid 兜底）又可能撞 key（duplicate 返回空 workers）。
9. **资源生命周期无归属**（P1-51/52/53、P1-63、P1-11/19）：后台任务、连接池、boto3 client、无界字典各建各的，无统一登记-清理机制；启动 try 作用域过晚使"泄漏"成为默认行为。
10. **宽 except 把失败伪装成成功/空结果**（P1-64/66/67、P1-47、P2-5/6）：DB 异常→空行、解析失败→空目录、模型失败→错误文案塞 text、异常→400——全链路"故障不可见"是同一文化问题。
11. **前端生命周期与竞态无范式**（P1-57/58）：KeepAlive 下无 onDeactivated、异步回写无请求序号/AbortController，各组件各自踩同一个坑。
12. **“持久化事实”与“派生动作”不在同一提交边界**（P0-34、P2-13；P0-35 已修复）：子任务终态/审批记录先落库，父续跑/ToolJob 后创建，仍缺 outbox、原子提交或恢复扫描。P0-35 的最终消息和完成事件现已同事务提交，不再把它列作现存半状态。
13. **同一工作项存在多套不一致租约且无 fencing**（P1-74/75、P0-20）：Redis marker、PG claim、运行租约和业务超时分别计时；完成/失败接口不验证 owner，过期 worker 可以写新 owner 的状态。
14. **数据库 schema 所有权分散**（P1-77）：34 个运行时模块自行 CREATE/ALTER/INDEX，Alembic 无版本文件；应用启动同时承担建表、升级、索引和业务服务四种职责。P1-13 已在第五轮复核中撤销，不再作为该根因的证据。
15. **质量门只验证“可转译/有部分测试”，没有验证契约完整性**（P1-80/81、P2-20/22/24）：Vite build 不做 TS/SFC 类型检查，live suites 默认跳过；第六、七轮补充了个别工具与 SSE 事件回归，但 AI 分片和完整协议仍缺正式前端回归，依赖审计未成为发布门，成功产包不等于可发布。
16. **可观测数据没有生命周期与部署模型**（P1-78/79）：label 消失不清零，registry 又按进程隔离；指标可能同时出现旧值、少算和 scrape 间倒退。
17. **把审计事件同时当作实时字节流**（P1-82/83；P0-35 的最终提交窗口已修复）：每个模型 chunk 先写持久化事实再向前端消费，仍放大数据库事务；最终 transcript 与完成事件现已原子提交，逐 chunk 成本及完整流协议另行治理。
18. **前后端事件枚举没有单一契约**（P1-4/30、P2-24；P1-84 与 P2-23 已局部修复）：后端可新增并实发事件，前端靠分散字符串白名单与手写 payload 解析；虽已修复 skipped 终态和 SSE 坏帧入口，仍缺共享 schema、穷举 reducer 检查和真实事件样本契约测试。
