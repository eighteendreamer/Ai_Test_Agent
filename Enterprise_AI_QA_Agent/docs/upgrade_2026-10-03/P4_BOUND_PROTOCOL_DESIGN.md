# 影响响应 v4：固定身份由系统绑定

研究基线：3d71c589，2026-10-05。完整P0—P5仍未完成。

## 依据与采用方式

上一轮实际自动流程的首响应将已给定单元UUID中的d27写成4b27，unit_mismatch拒绝了本来需要的补读。原请求、原响应、核验和对象字节保存在p4-default-model-automatic-first/。这里没有错误ID的可靠纠正依据，不能通过模糊匹配、忽略核验或修改原响应恢复。

当前impact_calls按冻结seed/输入/清单构造请求，read_request会重新核对请求，impact_batches核对原文切片和固定完整版本/字面路径。采用这些实际能力：后端继续拥有任务、单元、版本和哈希的权威身份；模型通过本次固定目录的短引用选择资料、用例和规则。分析输出还原成现有DocumentImpactDecision，再走已有读范围、未读引用、原文切片、哈希及JSON值核验。原模型输出和还原后的核验结果分别持久保存。

v4模型响应不包含当前单元、正式版本ID或哈希。来源S1、段P1、用例C1、差异D1、规则R1的映射由冻结清单及已验证协调上下文确定；每次同单元续读保留稳定映射和此前完整消息。未知短引用拒绝，不猜测正确身份。资料目录仍不等于读取正文；完整用例和自身说明不得缩减。

新提交采用impact-call-v4/impact-response-v2；旧v2/v3请求按其seed继续构造和核验，原消息、哈希和终态不改写。现有正式API、前端结果类型和PG表不变，模型wire Schema是内部新增版本；配置继续MySQL，固定任务/检查点PG，大对象RustFS。协议版本是实现契约，不另建用户配置或绕过现有任务策略。

旧协议专项明确注入v3工厂，继续证明历史兼容；新专项明确走生产默认v4，覆盖真实MD/DOCX/PDF和两适配器、受控HTTP及实际存储。真实默认模型使用v4的新任务验收，保留旧未知和原失败，不重发旧任务。生产API/独立Worker另验新提交；受控响应不能冒充真实语义判断。

## 验证要求

- 回放本轮实际误写响应：旧v3仍拒绝，v4通过新的短引用响应绑定到精确原单元；没有改写原响应。
- 固定目录必须与原清单一致，原文范围/quote、未读用例、False/0/null及错误字面路径仍拒绝不一致。
- 补读转换成既有selection，续读保留完整消息和稳定绑定；规则R1还原为固定rule id再检查逐规则用例覆盖。
- 跨项目/跨版本替换、任意正式ID、未知短引用及请求目录篡改不能进入候选；保存响应后再核验。
- 旧请求全文重建相同；新结果历史读取/终态投递不发模型，预算和unknown规则保留。

本轮先实施身份职责修正；推理任务聚合、阶段预算调度、拒绝反馈、需求评审/矩阵/增量及其余P0—P5继续按原目标推进，不把v4通过当成完整影响闭环。
