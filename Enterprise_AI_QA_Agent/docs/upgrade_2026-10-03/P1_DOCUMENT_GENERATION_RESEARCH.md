# 普通需求文档模块生成调研

本轮范围：普通文档独立提交、模块进度、固定来源和失败模块恢复。默认 Step 真实模型验收按用户决定暂缓；本轮使用受控 HTTP 模型验证生产传输及持久链路，不据此声称生成质量通过。

## 实际依据与决定

- `case_service.py:generate` 与 `generation_pipeline.py:ProjectTestCaseContextProvider`：普通生成一次整批调用，默认至多五份文档、每份 12000 字符、合计 48000 字符；没有持久模块任务。保留旧入口兼容性，新增基于指定解析快照的持久入口。
- `incremental_generation_sources.py:capture`、`postgres_generation_task_store.py:_submit_group`：已有持久生成要求正式需求版本、原评审及影响任务。本轮普通文档不伪造这些依据，新增独立来源契约。
- `parsing_service.py:read_snapshot`：已校验 RustFS 原结果大小、SHA、原件资产、解析器及配置。普通生成固定这份解析快照，不读取当前 Markdown 预览覆盖它。
- `case_generation.py:GenerationSnapshot.check_hash`：现有快照按完整序列化内容校验。新增独立 scope 版本，不向旧快照添加默认字段；既有组、模块、重试、响应收据契约继续复用。
- `generation_task_service.py:execute/retry`、生产生成 Worker：调用前保存意图，保存原响应后再原子提交草稿；失败模块创建子任务，终态不可重领；调用结果未知不重发。普通来源接入同一路径，不另建调度器、缓存或重试算法。
- 对照报告 5.5 与 `项目借鉴/ai_test_agent/skills/ai_case_generator.py`：参考按模块生成并检索切片，但包含截断回退。首期按解析章节确定不重叠范围，每次生成携带完整固定文档和当前焦点范围；不采用截断回退。超过既有 MySQL 策略或固定模型预算时，模块明确失败，仍保留可检查、可重试的固定请求。长文容量优化仍需另行验证。
- 本地课程《测试数据合成与用例自动生成》4.1：真实失败用于验证修复。《评测工程化与CICD》对应版本可追溯原则由现有固定快照、收据实现；本轮不将生成完成解释为业务覆盖充分或测试执行通过。

## 分块语义

选择出现多个章节的最浅层级；只有一个章节或没有章节时用单一模块。以该层级章节起点划分，首模块包含前言，子章节和表格随所属范围保留。所有范围顺序连续覆盖全部解析文本，不重复、不遗漏。每个请求同时带全文，以便理解跨章节约束。范围覆盖只证明输入没有丢失，生成覆盖率仍需用例评审。

## 验证设计

真实 Markdown 上传、独立解析 CLI、生产 API、MySQL 策略、PostgreSQL 组/模块/草稿、RustFS 固定对象、独立生成和恢复 CLI。三个模块中一个长响应超过原策略，另两个完成；提高当前策略仅用于新恢复子任务，复用长响应且无额外 HTTP 请求，原组与失败记录保持原样。另验证 API 重启后的原请求回查、终态重投、项目隔离及对象 SHA/大小。前端补独立入口、来源展示及已有任务详情/重试消费方，再运行类型检查、组件测试与实际页面验证。

## 实际结果

- before：1 失败，25.58 秒。上传和真实 Markdown 解析成功，普通持久生成 POST 返回 404；完整 HTTP/CLI 记录保留。
- verified：1 通过，63.98 秒。三个模块 2 成功/1 保存响应后失败；新子任务提高响应限制、复用原响应成功；仍只有 3 次真实 HTTP。原组和原失败任务不变，四个终态重投不调用模型，其他项目无法读取。
- product：1 通过，105.79 秒。构建的 App／实际 Chromium 文档页面提交普通生成，服务端成功但丢失回复后刷新回查原组；三个模块进度、固定任务详情、完整业务 JSON、原响应可读，无页面错误。
- formats：1 通过，133.67 秒。重复上述真实流程并加入普通 DOCX（3 模块、表格）和文本 PDF（1 模块、分页及结构警告）。四个生成组共 10 次模型 HTTP；原失败子任务和终态回放均不增加发送。生成前修改当前模板和项目策略，原请求仍使用原固定模板及限制。实际下载 14 个 RustFS 范围/响应对象，逐一校验大小和 SHA；原文件、截图、双流和完整收据保留。
- 既有增量 Worker／恢复回归：4 通过，34.17 秒，覆盖三格式生成和已保存响应恢复。
- 解析／普通分块／原生成器契约：25 通过，1 跳过，4.85 秒。跳过项为既有解析证据导出测试，其要求单独指定输出目录；真实文件已由本轮生产流程保存，未把该项算通过。
- 前端：类型检查退出 0；6 文件 67 项通过，包含普通页面、原增量页面、任务详情、重试、解析和 API 客户端。初次新增 API 导出缺三处测试 mock，以及新增测试使用了当前 tsconfig 不支持的 Array.at 和未收窄的 JSON 字面量类型，已修正；生产源未因此改变编译配置。

范围限制：章节输入覆盖不是用例覆盖率证明；本轮是受控 HTTP 模型的产品链路验证。默认 Step、实际业务生成质量、长文容量和规模预算仍待验收。部分/无文本解析不报告全量生成，必须先处理解析不足；完整文本 PDF 保留结构不可还原的警告。首期仍携带完整文档上下文，不宣称大文档检索或流式模块发现已完成。
