# 原工具可靠返回中的对象与清理证据

研究基线：`186679a8`。依据为6.44多对象与GET误报的真实失败、6.45同条目提前清理对照、原ToolJob观察/结算事务、逻辑操作索引和本地Agent轨迹课程。

## 根因与采用做法

原回执只保留模型选择的步骤输出，第二次合法创建可以被遗漏。`tool_output_observation`保存原返回SHA，但结算允许增加交付说明；不能事后把当前输出重算的SHA当作原返回SHA。可靠观察事务是保存对象证据的正确位置，而不是最终回执的字段映射。

新增可选MySQL规划策略`case-effect-evidence-v1`，要求已有准备范围与逻辑操作策略；新计划在PG冻结。正式用例和prepare均可声明产生对象的字面量路径；正式预期来自完整固定content_json，prepare预期来自自身instructions。清理声明目前在prepare使用cleanup_sources，引用正式或prepare产生来源；不复制正式步骤作为准备指令。定义不推测注册/订单或HTTP方法，也不把工具成功当作业务效果。

证据预算为MySQL `effect_evidence_max_bytes`，启用时实际默认512000字节，随计划/完整上下文及原意图冻结。超过预算不截成成功采集：保留固定身份、原观察、实际识别数量、所需字节和超限诊断，完整值不可用；诊断元数据仍需保存。原工具返回保持可恢复，不因采集预算耗尽而重发或拒绝合法业务操作。正式项目设置可修改预算，不原地改变旧意图。

原工具上下文从完整固定正式用例或prepare编译证据意图，原动作领取核对意图与固定上下文。原可靠返回写入时，在同一个PG事务保存小型不可变证据：原Job/逻辑操作/绑定、原返回SHA与观察时间、路径实际值、检查结果和对象引用。原Job仍负责执行与恢复；没有第二套工具执行器。大原件与既有工件仍在RustFS，不复制完整返回到新表。

查询沿不可变逻辑操作索引读取指定项目/运行/计划的原Job。别名恢复没有第二份效果；真实不同逻辑操作分别保留。未知原Job没有对象证据，显示未获可靠观察，不把它当作零对象。交付结算、当前配置或用例版本变化不能改写原证据。

## 完整实施方向与边界

本步先连接固定声明、原领取、可靠观察事务及全部原操作查询，以实际HTTP和MySQL/PG/RustFS验证。之后把这些证据接入完整模型输入、逐对象清理覆盖、正式结果/页面，以及消费完成和未知只读查证。没有消费完成证据前不能宣称已阻止同条目提前清理；没有覆盖核验前不能宣称6.44三个失败已修复。
