# 阶段 4 第 5 轮执行报告：执行租约与 ToolJob 心跳稳定性

## 1. 本轮结论

本轮补强超大项目长时间执行期间的租约稳定性：RunItem 执行时由服务端自动续租，ToolJob 进入 running 后由 Runtime 自动发送 heartbeat，执行结束后统一清理后台 supervisor。心跳失败会留下结构化日志，并将本次用例结果降级为 `error`，禁止把租约失效的结果伪装成成功。

本轮没有实现在线过期 lease reaper，也没有把 `security_testing` 接入统一用例执行适配器；安全模式仍保留现有授权门禁，等待独立安全用例契约与 Verification 投影设计。

## 2. RunItem 租约续期

`TestRunExecutionService.execute_item()` 在 adapter 执行期间启动后台 heartbeat：

- 使用领取时的同一个 `lease_token`；
- 默认按照当前租约剩余时间计算续租时长，测试可注入更短的 heartbeat 周期；
- 每次续租调用既有 `RunService.heartbeat_item()`，不新增第二套租约存储；
- adapter 结束、异常或取消时停止并等待 heartbeat 任务；
- heartbeat 失败记录 `test_run_item_lease_heartbeat_failed`，并把结果写为 `error`，保留失败原因到 `actual.lease_heartbeat_error`。

这样可以避免性能测试、兼容性执行或超大套件执行超过默认租约后被错误回收，同时继续依赖既有 lease token 防止旧 Worker 写入结果。

## 3. ToolJob 心跳

`ToolRuntimeService.execute()` 在 ToolJob `mark_running()` 后启动后台 heartbeat：

- 默认每 30 秒刷新一次，可通过构造参数注入测试周期；
- ToolJob 消失或 heartbeat 抛错时写结构化日志 `tool_job_heartbeat_failed`；
- 工具正常完成、失败、审批等待或异常返回时，`finally` 均会停止并回收 supervisor；
- 继续复用 `ToolJobService.heartbeat()` 和现有持久化 store。

本轮只处理租约保活，不主动取消底层长任务；后续可在明确的任务取消契约下增加失联中止策略。

## 4. 测试覆盖

新增回归用例验证：

- 慢 adapter 执行时间跨过 RunItem heartbeat 周期；
- heartbeat 被多次调用且每次使用同一 lease token；
- 慢执行最终仍可完成并写入 `passed` Result；
- RunItem heartbeat 失败时最终 Result 为 `error`，并保存错误上下文；
- ToolJob 慢 handler 执行期间 heartbeat 持续更新；
- ToolJob 完成后 `_keep_tool_job_alive` supervisor 已被清理。

## 6. 未处理风险与边界

- 尚未实现在线过期 RunItem lease reaper；服务重启或 Worker 进程直接失联时仍依赖既有恢复流程；
- ToolJob heartbeat 失败目前记录日志但不主动取消底层任务；
- `execute_item()` 中 run/case/version 的读取仍发生在 heartbeat supervisor 创建之前，读取异常不会产生执行期间 heartbeat；
- `security_testing` 仍未接入统一用例执行，原因是当前通用 Runtime 调用链不能自动满足 verified target authorization；
- Smoke catalog 统一迁移与真实 PostgreSQL 容量基线仍待后续轮次。
