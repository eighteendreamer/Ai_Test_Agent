# 阶段 4 第 7 轮执行报告：Smoke 历史只读兼容视图

## 1. 本轮方案执行做了什么

本轮没有把旧 Smoke catalog 直接写入统一 `TestRun/RunItem/Attempt/Result` 表。只读审计确认旧数据存在不可逆语义差异：TEXT 主键、自由 `project_scope`、JSONB 聚合 `case_results`、缺少正式用例版本和执行 Attempt。直接搬表会制造不可执行的伪历史。

本轮采用方案 1.0 允许的局部调整：先提供显式绑定和只读兼容视图，保留物理迁移边界。

已完成：

- 新增 `agent_smoke_project_scope_bindings` 显式绑定表；
- 新增 `PUT /api/v1/projects/{project_id}/legacy-smoke-bindings` 绑定人工确认的 `project_scope`；
- 新增 `DELETE /api/v1/projects/{project_id}/legacy-smoke-bindings/{project_scope}` 解绑；
- 新增 `GET /api/v1/projects/{project_id}/legacy-smoke-runs` 只读历史接口；
- 查询只使用正式项目 ID → 人工绑定 Scope → 精确 `project_scope` 过滤，不按名称、URL、host 或图谱自动猜测；
- 使用 `started_at DESC, run_id DESC` keyset 分页和数据库索引，避免 offset 深分页；
- 直接读取 PostgreSQL `metadata` 快照中的 `case_results`，不回读可能被同一 plan 后续运行覆盖的 MinIO 固定 URI；
- 保留 `legacy_run_id`、`legacy_plan_id`、`legacy_case_id` 和原始状态；
- 将 `partial` 映射为只读展示状态 `blocked`、`not_run` 映射为 `skipped`，同时保留 `legacy_status`；
- 前端“测试项目”页面新增“旧冒烟历史”标签、Scope 绑定/解绑和只读分页展示；
- 旧记录不暴露 claim、execute、heartbeat 或一键回归入口。

## 2. 相比方案 1.0 的进度

本轮完成了阶段 4 中“Smoke catalog 统一历史入口”的安全前置层：

```text
人工确认 scope
  → 绑定正式 project_id
  → 只读查询 legacy run metadata
  → 展示逐例原状态/证据计数
```

这让项目历史可以看到旧 Smoke 记录，但没有错误地把旧记录当成可执行测试资产。

仍未完成的物理迁移门槛：

- 尚未生成正式 TestCase/Version/Suite/Run/Attempt/Result；
- 尚未增加 import ledger、`--dry-run` 和显式 scope→project 映射 CLI；
- 尚未实现 canonical Result 对旧 Smoke run ID 的重复投影排除；
- `security_testing` 仍保持授权阻断；
- 尚未进行真实 PostgreSQL 大规模并发和查询计划基线。

## 5. 下一轮要做什么

1. 设计 Smoke 历史物理导入的 `import ledger` 数据契约，唯一键使用 `source_system + legacy_run_id/case_id`；
2. 编写默认 dry-run 的迁移 CLI，只接受显式 `scope → existing project_id` JSON，不自动建项目、不自动猜 scope；
3. 先实现导入预检报告（可导入、未绑定、坏 metadata、已 canonical、状态映射），预检通过后再考虑写入；
4. 继续保留旧表和只读视图，迁移失败不能破坏原始历史；
5. 物理导入完成前，正式回归 API 继续拒绝 legacy source。
