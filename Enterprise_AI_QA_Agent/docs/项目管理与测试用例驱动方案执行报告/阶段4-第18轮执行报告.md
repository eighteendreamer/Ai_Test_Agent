# 阶段 4 第 18 轮执行报告：并发领取死锁修复与执行证据链

## 1. 本轮方案执行做了什么

第 17 轮已完成审批拒绝终结与取消补偿，但真实 PostgreSQL 多连接压测暴露了 RunItem 领取路径的生产级死锁。本轮先复现并修复锁升级根因，再建立可重复的真实 PostgreSQL 并发验收，以及安全用例从 ToolRuntime 到最终 Result 请求的生产组件证据链。

主要变更：

- `PostgresTestRunStore._lock_run()` 将 Run 行锁从 `FOR UPDATE` 收敛为 `FOR NO KEY UPDATE`。Run 刷新只修改状态、统计、时间和 JSONB，不修改主键；新锁仍串行保护 Run 状态更新，同时不与 Attempt 外键检查持有的 `KEY SHARE` 冲突。
- 新增锁级别回归测试，并同步修正 PostgreSQL Store 测试桩和锁顺序断言，防止后续退回会触发死锁的锁级别。
- 新增 opt-in 真实 PostgreSQL 测试，使用随机独立表验证 12 Worker 对 480 个 RunItem 的 `SKIP LOCKED` 原子领取：每个 Item、Attempt、lease token 均唯一，无重复领取、无遗漏、无死锁。
- 同一真实数据库测试验证 32 个并发 Approval 决策的 CAS：唯一终态，同态请求幂等成功，异态请求确定性冲突。
- 使用生产 `ToolRuntimeService`、`ToolJobService`、`InMemoryToolJobStore`、`CaseExecutionAdapter` 和 `VerificationService`，验证安全固定用例经确定性本地 Runner handler 后，ToolJob、Artifact、Verification 和最终 `RunItemCompleteRequest` 的 ID 与状态一致，Runner 只执行一次。
- 新增 live 测试默认跳过，只有显式设置 `RUN_LIVE_POSTGRES_TESTS=1` 才连接本机 PostgreSQL；每次创建随机后缀独立表，并在 `finally` 中按外键逆序清理，不触碰公共业务表。

## 3. 根因与依据

真实 PostgreSQL 复现链路：

1. 多个领取事务分别用 `FOR UPDATE SKIP LOCKED` 锁住不同 RunItem。
2. 插入 Attempt 时，`run_id` 外键检查在同一 Run 行取得 `KEY SHARE`。
3. 每个事务随后调用 `_refresh_run_in_cursor()`，旧实现尝试把 Run 行升级为 `FOR UPDATE`。
4. `FOR UPDATE` 与其他事务持有的 `KEY SHARE` 冲突，多个事务形成锁升级环并触发 `DeadlockDetected`。

采用 `FOR NO KEY UPDATE` 的依据：

- PostgreSQL 15 官方 [Explicit Locking](https://www.postgresql.org/docs/15/explicit-locking.html) 锁冲突矩阵明确：`FOR KEY SHARE` 与 `FOR UPDATE` 冲突，而与 `FOR NO KEY UPDATE` 不冲突。
- Run 刷新不修改主键，因此不需要最强的 `FOR UPDATE`；`FOR NO KEY UPDATE` 仍与其他 Run 状态刷新事务互斥，保留统计和终态转换的串行语义。
- 没有添加业务层死锁重试，因为重试只能缓解表象，不能消除确定性的锁升级冲突。

测试工程依据：

- `项目借鉴/llm-testing-course/Agent轨迹与协议鲁棒性.html`：验证状态迁移、重复执行、超时恢复和终态不可重领。
- `项目借鉴/llm-testing-course/评测工程化与CICD.html`：执行环境、用例版本、结果和证据必须可追溯。
- `项目借鉴/llm-testing-course/性能测试-通用篇.html`：逐级加压并记录吞吐与 P50/P95/P99。

| 唯一 lease token | `480 / 480` |

## 7. 局部影响评估

- 锁级别变化只影响 PostgreSQL TestRun 的 Run 行刷新，不改变 API、数据结构或 InMemory 行为。
- `FOR NO KEY UPDATE` 仍使同一 Run 的统计刷新串行化；不同 Run 可独立并发，RunItem 继续通过 `SKIP LOCKED` 分片领取。
- 普通对话、代码审批和不使用用例驱动执行的豁免模式不受影响。
- live 测试不默认访问数据库，不改变普通 CI 的外部依赖要求；需要数据库验收时可显式运行。
- 真实组件证据链没有发起外网请求或真实扫描，验证范围是系统内部生产组件的状态与证据投影契约。
